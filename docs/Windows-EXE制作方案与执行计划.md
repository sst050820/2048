# 凝合 · Windows EXE 制作方案与执行计划

日期：2026-10-19  
项目：`E:\Codex\2048`  
状态：交付形式已确认；本文为详细设计与执行计划，尚未实施桌面代码或生成 EXE。

## 一、已经确定的交付目标

用户选择 **Windows 64 位免安装版**：下载 ZIP → 完整解压 → 双击 `凝合.exe` → 开始游戏。

成品必须满足：

1. 不要求玩家安装 Node.js、执行命令或启动本地服务器。
2. 游戏资源随程序分发，首次启动就能断网游玩。
3. 使用独立窗口，显示游戏名称与图标，支持鼠标操作、窗口缩放和全屏。
4. 保留现有软球物理、合并规则、中文界面、主题、成就和音效。
5. 退出后可以续玩；同一 Windows 用户移动游戏目录或升级应用后，存档仍可读取。
6. 代码继续维护在现有 `E:\Codex\2048`，不另建一个完整项目副本。

“免安装”指程序不用安装，并不意味着只发一个裸 EXE。运行所需的 DLL、资源和运行时目录必须一起保留。也不意味着存档跟着 U 盘跨电脑移动：首版存档保存在 Windows 用户目录。

## 二、技术方案与选择理由

| 方案 | 适用性 | 决定 |
| --- | --- | --- |
| Electron + Electron Forge ZIP | 内含浏览器运行时，直接复用现有 HTML/CSS/JS，适合免安装分发；包体会明显大于网页文件 | 首版采用 |
| Tauri / WebView2 | 有机会缩小应用包，但要处理 WebView2 环境及额外原生工具链，需重新验证渲染差异 | 首版不采用 |
| PWA | 当前已有基础支持，部署较轻，但安装入口和运行依赖浏览器 | 保留现有网页版用途 |

选择 Electron 是为了复用现有游戏，并让分发包携带明确的运行环境。它不会自动修复物理或性能问题，也不能在未经实测的情况下保证比浏览器更快。

Electron、Forge 和打包依赖在实施时查询官方稳定版本、检查兼容性并锁定准确版本；不在计划中猜测版本号。首版以当前 Windows x64 电脑验收。Windows 10/11 的支持范围以选定 Electron 版本和实际测试环境记录为准，不将未测系统写成已通过。

## 三、玩家使用设计

### 启动与窗口

- 名称：凝合；程序文件名：`凝合.exe`。
- 使用现有游戏图标生成 Windows `.ico`，不重新设计画面。
- 保留 Windows 原生标题栏，提供最小化、最大化、关闭。
- 首次启动优先使用约 1100×800 的窗口；空间不足时按当前显示器工作区缩小，保证窗口和按钮可见。
- 后续启动恢复有效的窗口位置、大小和最大化状态；显示器拔除后必须把窗口移回可见工作区。
- F11 切换全屏。保留现有 Esc/P 暂停、M 静音、K 切换主题、L 深浅模式功能，不抢占现有 Esc 行为。
- 再次双击程序时激活已经运行的窗口，避免两个实例同时写同一份进度。
- 最小化或切换到其他应用时暂停游戏；返回时保持暂停，由玩家继续，避免切回瞬间意外发射。

### 离线与资源加载

桌面窗口读取随包携带的 `www/`。不依赖 GitHub 在线页面，也不使用开发服务器。

使用固定的应用内地址 `ninghe://app/index.html`：主进程注册本地协议，只返回打包的游戏资源。只允许已知主机、GET/HEAD 和资源目录内的路径；拒绝路径越界、错误编码、未知资源与远程导航。

现有 Service Worker 仅在 HTTP(S) 下注册，桌面协议不会启用它；桌面离线能力来自本地资源，避免旧 PWA 缓存覆盖新程序。网页版本的 PWA 行为继续保留。

### 存档与更新

- 正式版采用固定的 Windows 用户数据位置，例如 `%APPDATA%\Ninghe`，首次发版前确定后不随版本号改变。
- 固定应用内地址和持久会话，使现有 `soboscuba.*` localStorage 键与存档格式继续使用。
- 开发和自动化测试采用独立数据目录，不能清理或覆盖正式玩家存档。
- 浏览器版旧存档不会自动出现在 EXE 版中；首版不读取浏览器个人资料。手动导入/导出可在后续单独设计。
- 正常关窗采用“暂停并保存 → 收到完成确认 → 刷新存储 → 关闭”的过程；不是点击关闭就立即销毁窗口。
- 保存确认设置有界等待。超时或失败时提示“重试 / 取消退出 / 直接退出”，不能假装保存成功，也不能让窗口无限卡住。
- 当前 `store.set` 会吞掉写入异常。实施时为退出存档增加可判断的写入结果，保留旧调用兼容性；不在本次重写游戏存档结构。
- 强制结束进程、断电不能承诺保存最后一帧；沿用自动保存策略，正常关闭需要单独验收。
- 首版通过下载新 ZIP、退出旧程序、解压新目录更新；新程序复用同一用户数据目录。无需自动更新服务。

## 四、程序结构

```text
E:\Codex\2048\
├─ desktop\
│  ├─ main.cjs                应用生命周期、单实例、窗口及全屏
│  ├─ preload.cjs             有限的暂停/保存请求与完成确认
│  ├─ protocol.cjs            应用内资源协议与路径校验
│  ├─ window-state.cjs        窗口状态读写与可见区域修正
│  └─ assets\icon.ico         Windows 图标
├─ forge.config.cjs           Windows x64 打包及 ZIP 配置
├─ www\                      现有游戏源码与资源
├─ tests\desktop\            桌面生命周期、协议、存档回归
├─ tools\                    现有构建及新增桌面辅助工具
├─ docs\                     制作计划、测试记录和使用说明
├─ out\                      本地生成的包与测试输出，不提交 Git
└─ package.json               新增桌面命令，保留网页命令
```

主进程负责窗口、文件路径和应用退出；游戏页面仍负责物理、渲染及游戏状态。预加载层只提供暂停和保存握手，不向页面暴露文件系统、命令执行或通用 IPC。

窗口开启 `contextIsolation` 与 `sandbox`，关闭 `nodeIntegration`；不允许游戏页面打开任意新窗口或跳转远程页面。为本地资源设置明确的内容策略，需兼容现有脚本和动态主题；若需要将网页末尾内联脚本提取到独立文件，应同步调整打包脚本和 PWA 资源清单并做回归。

打包使用资源白名单，只包含桌面入口、必要依赖、`www/` 和必要许可文件。不把测试截图、备份、参考视频、审查资料或开发依赖放进成品。保留 Electron 运行时和现有资源的许可说明。

## 六、阶段关系与执行节奏

```text
基线与工具链 → 桌面可玩 → 窗口与输入 → 存档可靠
                                      ↓
文档与交付 ← 成品回归及性能对照 ← 生成免安装包
```

先完成能启动的最小版本，再处理退出与持久化，最后打包和验证。依赖下载及桌面验收时间不确定，不预先承诺固定小时数；以各阶段的完成标志推进。

执行时每个阶段汇报：已完成内容、实际验证结果、阻断问题和下一阶段。只有达到验收标准才更新为完成，不把“已写代码”“能启动开发版”和“成品验收通过”混为一谈。

首版暂不增加自动更新、账号、云存档、联网排行榜、付费、安装向导或新的物理效果。这些可在免安装版稳定后另行规划。
